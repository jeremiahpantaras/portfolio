## Deviations from the approved plan
1. **Phases 1 and 2 were executed together for the pages**, because every sub-page had to be rewritten onto the shared shell anyway; doing them twice would only create throwaway code.
2. **No `redesign/descent` branch and no commits** (instructions: do not change branches or commit unprompted).
3. **`three` is pinned to 0.182.0, not 0.186.x.** `@react-three/fiber` 9.8.2 still uses `THREE.Clock`, which three deprecated in 0.183 and logs a console warning for. 0.182.0 is the last release without it and is what the React Bits 3D components target. Revisit when R3F ships Timer support.
4. **Console-blocking script kept, guarded to non-local hosts** instead of removed (the plan's own fallback; decisions 6a).
5. **Waterline simplified:** the plan's custom scroll-velocity-driven path regeneration was replaced by React Bits `CurvedLoop`'s built-in `wave` shape + `scrollBoost`, which already reacts to scroll speed and handles pausing/reduced motion. Less custom code, same effect.
6. **React Bits `SplitText` not vendored.** GSAP's own `SplitText` (already installed) does the same job and is used directly, so two libraries do not duplicate one function. Only `CurvedLoop` and `ScrollReveal` were vendored (with documented local edits).
7. **Hero entrance does not wait for fonts** (plan: ≤ 600 ms wait). SplitText's `autoSplit` re-splits when the font swaps in, so a wait is unnecessary.
8. **Nav entrance is CSS-only** and the hero timeline no longer animates the nav (it is persistent across routes).
9. **Image tooling:** a `cwebp`-based script instead of `sharp` (no npm dependency).
10. **`/projects` tag filter not built** (it was optional); re-mounting filtered rows would have needed extra reveal handling.
11. **Verified badge** next to the name was dropped from the hero and the chat header (the plan moved it out of the hero; it imitates a social-platform verification mark).
12. **Chat is now site-wide** (every main-site route) rather than only on the home page.
13. **`chunkSizeWarningLimit: 1000`** in `vite.config.js` for the intentionally large lazy 3D chunk.

## Third follow-up: the aurora follows the page and changes sides
- **Behaviour:** `src/components/motion/AuroraTrail.jsx` replaces the aurora that lived inside the hero. With motion, it becomes one `position: fixed` layer that follows the home page and alternates sides section by section: right at the hero, left at About, right at Work, left at Capabilities, right at Experience, left at Gallery, and so on. Two copies (the second mirrored) cross-fade and slide a few percent leftwards/rightwards while you scroll between section centres (eased with a smoothstep and `gsap.quickTo`), so the glow appears to travel. Native scrolling is untouched.
- **Readability:** past the hero the glow dims to 50 % and its white-hot core and streak fade to 18 %, so text stays legible. Verified on real screenshot pixels with the text hidden (worst case across the brightest left and right areas): muted text 5.75:1, small subtle labels 4.68:1. An earlier 60 % strength measured 4.07:1 for the small labels, so it was reduced, and `--color-fg-subtle` was lightened from `#83838b` to `#92929b` (site-wide, slightly brighter metadata text).
